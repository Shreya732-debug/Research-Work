# Supervisor demonstration: Disclosure Verifier

Prepared 26 October 2026. This is a working **deterministic reference verifier** with a local browser interface. It is not a newly trained language model. It demonstrates the project's decision contract on prepared pilot facts while independent annotation review remains pending.

## Run it on your laptop

1. Download the repository branch containing this change using GitHub's **Code → Download ZIP**, then **Extract All**. Alternatively, extract the standalone `supervisor_demo_bundle.zip`.
2. Open the extracted `code` folder and double-click **4_SUPERVISOR_DEMO.bat** on Windows. Keep its terminal open. A browser should open at `http://127.0.0.1:8765/`.
3. If the browser does not open, copy that address into Chrome or Edge. If Python is not installed, install Python 3.11 or newer from https://www.python.org/downloads/ and enable **Add Python to PATH**. If Windows provides the Python launcher instead, open a terminal in `code` and run `py -3 supervisor_demo.py`.
4. On macOS/Linux, open a terminal in `code` and run `python3 supervisor_demo.py`.
5. If port 8765 is occupied, run `python supervisor_demo.py --port 8766` and use the address printed in the terminal.
6. To stop, press Ctrl+C in the terminal. The demo runs locally; it is not a publicly deployed website.

No `pip install`, API key, paid model, GPU or internet connection is required to run the verifier. Opening the external SEC source links does require internet. This package does not install Python for you or change your browser settings. The general `requirements.txt` applies to the other project scripts, not this demo.

## What to show in five minutes

Use the guided buttons in order. The first five use exactly the same prepared claim: **SunPower reported fiscal-2022 net income attributable to stockholders of USD 56.037 million.** The disclosure policy and cutoff supply its interpretation.

| Button | Policy / cutoff | Reference output | What to explain |
|---|---|---|---|
| Original report | Original as filed; 2023-12-19 | S | The original named report disclosed this number. |
| Corrected report | Corrected; 2023-12-19 | C | The later selected report discloses 42.849 million for this row. |
| Before withdrawal | Active evidence; 2023-10-18 | S | The original is the active matching report in the eligible packet. |
| Withdrawal gap | Active evidence; 2023-10-25 | U | The 8-K is eligible, but the replacement annual report is still future evidence. |
| After replacement | Active evidence; 2023-12-19 | C | The replacement is now eligible and conflicts with the old amount. |
| Rounding challenge | Separate exact-unrounded claim P018 | U | A rounded displayed amount does not establish exact underlying equality. |

Scroll down to show the source links, official filing dates, excluded future documents and selected numerical facts. Explain that historical original-as-filed questions can establish what an old report said even after withdrawal. The active-authority question is different.

The displayed simple control is B4W. It agrees with P on the guided examples. Do not claim a new algorithm or superior accuracy from the demonstration. The source facts and status links were prepared in advance; the software does not infer their validity from the original filing text.

## What remains unresolved

The previously identified automatic-data assumptions, inferred precision from trailing zeros, bare/full prompt confound and LLM resume-versioning issue are **not resolved by this demo**. It uses the prepared pilot facts. Do not use the existing bare/full comparison as evidence of temporal-reasoning failure until the experimental design is corrected. Do not call the automatic candidate families human-validated.

The resolver expects normalized metrics, periods, units and preassigned original/corrected roles within a single issuer packet. It does not perform raw-document retrieval, accounting interpretation, currency conversion or arbitrary free-text claim parsing. More complex multi-version scope relationships need separate cases and validation.

The day-level rule deliberately excludes documents filed on the cutoff day. It is a conservative evaluation convention, not a legal rule or exact reconstruction of public dissemination. Answers concern the supplied packet, not all information available to the market.

Students remain responsible for understanding the work, running and explaining the demo, independently checking evidence, discussing scope with the supervisor, and taking responsibility for any submission. AI assistance and annotation provenance must be disclosed as required by the venue.

A financial expert is not required to begin this narrowly defined pilot. Two trained students can independently inspect explicit rows, periods, units and correction notices. Record disagreement and prior exposure; leave genuine accounting ambiguities unresolved or exclude them. This is not expert validation.

There is no defensible publication probability out of 100 from the current evidence. Acceptance depends on a verified literature gap, annotation reliability, meaningful evaluation, venue fit and review. Do not abandon the direction solely because the team lacks financial qualifications. Use these decision gates instead:

1. Can two students consistently annotate the explicit evidence after calibration?
2. Do the reviewed cases exercise a task not already adequately covered by the closest literature?
3. Do controlled model comparisons yield an informative finding beyond compliance with a template, including a useful negative result if simple rules suffice?
4. Does the supervisor agree that the validated scope fits the project timeline and a suitable venue?

Do not add XAI, fraud detection or a new trained architecture just to increase apparent complexity. A benchmark/evaluation contribution remains a possibility, not a promise of publication.
